# パス＆プレイ設計メモ

同じ端末を回して遊ぶローカル対面モードの設計。**サーバー不要・オンライン対戦とは別物**。
実装そのものはこのメモの計画に沿って別ランで段階的に行う。

作成日: 2026-11-11 / 対象: `index.html`（単一ファイル、約116KB、8人固定）

## 1. 目的

- 友だちや家族と1台のスマホ／PCを回して Fake Bloom を対面で遊べるようにする。
- ソロ（人間1人 + CPU 7人）の体験は壊さない。モードはタイトル画面で切り替える。

## 2. 現行コードの前提（2026-11-11 時点で確認）

- 8人固定。`names = ["ルナ", "ミオ", "ユイ", "カノン", "スズ", "リリ", "ノア", "エマ"]`。
- `setupGame()` で役職を `roleBag` にシャッフル配布。内訳はインポスター1〜2人（`fakeGirl` / `mimic`）、
  ボマー（設定により有無）、`baka` 1人、残りがイノセント側（`apprenticeSeer` 固定 + 抽選）。
- 人間は `state.playerId` 1人だけ（ランダム）。それ以外はすべて CPU。
- フェーズ遷移: `night` → `morning` → `discussion` → `vote` → `night` … → `end`。
- 夜: 人間の夜行動は `runNight()` → `resolveNightActions()`、CPU の夜行動は `cpuNightActions()` で一括計算。
- 議論: `morningToDiscussion()` / `discussionToVote()`。CPU の発言は `pickTalkLine()` で自動生成される。
- 投票: `doVote()` で人間の投票後に CPU が `suspicion` に基づいて投票し集計する。
- 役職ごとの夜行動は `ROLES[roleKey].nightAction`（`investigate` / `protect` / `track` / `block` /
  `lookout` / `trap` / `revive` / `attack` / `plant` / なし）。`allowSelf` で自分選択の可否が決まる。
- インポスター同士の情報共有は `getFakeAlliesText()`（人間1人向けに仲間の名前を出す）。
- 設定は localStorage（`SETTINGS_KEY`：インポスター人数・ボマー有無・難易度・効果音）。
  戦績・実績も localStorage（`STATS_KEY` など）。単一のグローバル `state` が試合全体を持つ。

## 3. モード設計

### 3.1 モード選択と参加人数

- タイトル画面の設定に「遊び方：ソロ / パス＆プレイ」を追加する（既存の `gameSettings` に項目追加。
  保存形式は後方互換を保ち、未設定時はソロ扱い）。
- パス＆プレイ選択時は参加人数（人間プレイヤー数）を 2〜8 人で選ぶ。残りは CPU が埋める。
- 人間プレイヤーには番号（P1〜Pn）と 8人のキャラ名を割り当てる。キャラの割り当てはランダムでよい。
- 役職抽選・インポスター人数・ボマー有無・難易度は現行の設定をそのまま使う。
  難易度は CPU の強さのみに効かせ、人間同士の駆け引きには干渉しない。

### 3.2 役職の受け渡し（のぞき見防止が最重要）

- ゲーム開始時、各人間プレイヤーに順番に役職を提示する。
  - 「P2（ミオ）さんの番です。端末を受け取ったらタップ」のような**カバー画面**を出す。
  - タップでその人の役職（`showRole()` 相当：役職名・説明・インポスターなら仲間情報）を表示。
  - 「確認した」ボタンで再びカバー画面に戻し、次の人へ渡す。
- インポスター陣営の人間同士は、仲間確認のタイミングで互いの正体を共有する
  （現行 `getFakeAlliesText()` を複数人間対応に拡張する）。
- `baka` には偽表示役職（`fakeDisplayRoleKey`）だけを本物として提示し、本人にバカだとは知らせない（実役職は結果画面でのみ開示）。
- CPU の役職は表示しない（現行通り）。

### 3.3 夜行動の進め方

- 夜フェーズは「人間プレイヤーの夜行動入力」を順番に行う。
  - 各人の番ではカバー画面 → その人の役職に合った夜行動入力画面（現行の `runNight()` の
    ターゲット選択 UI を流用）→ 確認してカバー画面へ。
  - 能力なしの役職（村ガールなど）の番は「今夜は能力がありません」とだけ出して次へ進む。
    ただしバカの場合は表示役職としての行動画面を出す（現行のソロ挙動と同じ）。
  - 人間全員の入力が終わったら CPU の夜行動を `cpuNightActions()` で一括計算し、朝へ進む。
- 夜行動の結果（占い結果・スパイ結果・護衛の成否など）は、**翌朝ではなくその人の次の番**で
  個別に提示する。朝の全体報告（現行の `nightReport` / カットイン）は「誰が倒れたか」など
  全員共通の情報だけに留め、個人の調査結果が他人に漏れないようにする。
- ボマー（人間）の爆弾設置も同じ順番入力に含める。爆発は現行通り翌夜の解決時に処理する。

### 3.4 議論フェーズ

- 議論は口頭で行うのが前提。画面は議論タイマー（任意）と発言ログの表示に留める。
  タイマーはタイトル画面の設定で なし／1分／2分／3分から選ぶ（既定なし）。
  時間切れでも自動では投票へ進まず「時間切れ！」の合図だけを出す（口頭の議論を途中で切らないため）。
- CPU の自動発言（`pickTalkLine()`）は、人間プレイヤーの人数に応じて量を減らす。
  上限は `pnpCpuTalkCap()`：人間2人→4、3人→3、4人→2、5人以上→1。
  人間が多い試合では CPU の発言が議論を埋め尽くさないようにする。
  ソロは従来通り生存中の CPU 全員が発言する。
- マウス（`mouse`）の公開ボタンは、その人間プレイヤーの番にだけ表示する
  （現行は `state.playerId` 1人向けの表示条件なので、対象を「現在の番の人」に変える）。

### 3.5 投票の進め方

- 投票も夜行動と同じく人間プレイヤーごとに順番に入力する（カバー画面付き）。
- 人間全員の投票が終わったら CPU の投票を現行 `doVote()` の仕組みで計算し、集計・追放処理を行う。
- 投票中は他人の投票先が見えないこと。集計結果の表示は現行通り（票数と追放者）でよい。
- 政治家（`politician`）の2票分の重みは現行通り集計に反映する。

### 3.6 インポスター同士の扱い

- インポスター陣営に人間が2人いる場合、襲撃先は2人で相談して1人に絞る。
  入力は代表者1人が行い、もう1人がカバー画面越しに確認する形にする。
  （2人とも別々の襲撃先を入力して食い違う事故を防ぐため、入力は1回だけ）
- インポスターの人間が1人だけの場合は現行通りその人が襲撃先を決める。
- インポスターの人間同士の相談は口頭で行う。画面上では「インポスターの仲間と相談してください」とだけ案内する。

### 3.7 状態管理と保存

- `state.playerId`（単数）から「人間のプレイヤー ID 一覧 `humanPlayerIds`」＋
  「現在入力中の人 `currentTurnPlayerId`」へ拡張する。
- ソロ時は `humanPlayerIds = [playerId]` として従来通り動かし、既存の挙動を壊さない。
  夜行動・投票・議論の各処理は「現在の番の人」を参照する形に寄せる。
- 設定（`SETTINGS_KEY`）の保存形式は変えない。モードと参加人数は設定に追加するだけ。
- 戦績・実績（`STATS_KEY` など）はソロ用とパス＆プレイ用で分ける。
  パス＆プレイ用に別キー `fb_pnp_stats`…ではなく `fakeBloomPnpStats` を用意し、
  勝った陣営と各人間の役職別戦績を記録する。ソロの戦績は汚さない。
  タイトル画面にはパス＆プレイ専用の戦績パネルとリセットボタンがある。
  （フェーズ4で実装済み）

## 5. テスト観点

- `tests/` のハーネスに「人間2〜3人のパス＆プレイモード」シナリオを追加し、フルゲームが
  40日以内に完走すること（現行テストと同条件）。
- のぞき見防止の確認：他人の役職・夜結果・投票先が画面表示・ログに出ないこと。
- 回帰：ソロモードの既存テスト（`node --test` 全件）が通ること。
- スマホ実機での確認：カバー画面のタップ操作と 48px 以上のタッチターゲット（現行の設計基準）。

## 6. 決まっていないこと（endo への確認事項）

- 参加人数の上限・下限（2〜8人を想定しているが、2人でも面白いか）。
- 議論タイマーの有無と長さ（例：1分／2分／なし）。
  → フェーズ4で設定化した（なし／1分／2分／3分、既定なし）。
  時間切れでも自動では進まない。
- 戦績をソロと分けるか（分ける想定だが、合算でもよいか）。
  → フェーズ4で別キー `fakeBloomPnpStats` に分離した。
- 人間がボマーのときの爆弾入力も夜行動の順番入力に含める想定でよいか。
- 8人全員が人間の場合、CPU の議論セリフは不要になるか（完全口頭議論にするか）。
